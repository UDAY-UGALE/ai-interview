Documentation

You run your own backend. It holds the model-provider API key, and every client you hand out talks to it. This page covers deploying it and connecting a client.

The two halves

The backend is a container: FastAPI, no UI, no sound card. It takes audio over a websocket, runs voice detection and speech-to-text, decides whether a question was asked, and streams an answer back.

The client is a Windows desktop application. It has to be desktop software: it captures your system's audio output, and it draws a window that is excluded from screen capture. Neither is something a web page can do.

Deploying the backend

The deployable unit is a Docker image, which is what keeps it portable — the same image runs on Render, AWS ECS, or Azure Container Apps with nothing changed but environment variables.

Render (free tier)

  1. Push the repository to GitHub. Make sure .env is not committed — it is gitignored by default.
  2. New → Blueprint in the Render dashboard, and select the repository. It reads render.yaml.
  3. Paste your GROQ_API_KEY when prompted. APP_AUTH_TOKEN is generated for you — copy it from the service's Environment tab, it is what clients present.
  4. Check /health once the build finishes. It should return {"status":"ok"}.
  5. Check /version to confirm auth_required is true. If it is false, your token did not get set and the URL is open to anyone who finds it.

Anywhere else

docker build -t interviewcopilot .
docker run -p 8000:8000 \
  -e GROQ_API_KEY=... \
  -e APP_AUTH_TOKEN=... \
  interviewcopilot

The container binds 0.0.0.0 on $PORT (default 8000) and needs no volume, no database, and no other service. Point a load balancer with websocket support at it and it works.

One instance, for now. Session state and the answer stream are held in the process. Running more than one replica needs SESSION_STORE_BACKEND=redis first — otherwise a client's audio connection and its answer connection can land on different replicas and answers never arrive.

Configuration

Everything is an environment variable. The full list with defaults is in .env.example; these are the ones that matter for a deployment.

VariableWhat it does
GROQ_API_KEYYour model-provider key. Required.
APP_AUTH_TOKENShared secret every client must present. Leave empty only when the server is bound to localhost.
ANSWER_PROVIDERgroq, openai, anthropic or deepseek.
STT_PROVIDERgroq, openai, nvidia, or faster_whisper for a local model.
SESSION_LOG_ENABLEDPer-session transcripts to disk. Turn off where the filesystem is ephemeral.
CORS_ALLOW_ORIGINSOnly needed if a browser page calls the API. The desktop client does not need it.

Connecting a client

Put a interviewcopilot.json next to the executables:

{
  "api_url": "https://your-backend.onrender.com",
  "token": "the APP_AUTH_TOKEN from your backend",
  "session_id": "one-per-person"
}

Environment variables (INTERVIEW_API_URL, INTERVIEW_TOKEN, INTERVIEW_SESSION_ID) and command line flags both override the file, in that order. Running from source with no configuration at all falls back to http://127.0.0.1:8000, so local development needs no setup.

Building the client

pip install -r requirements-client.txt
pip install pyinstaller
powershell -File scripts\build_client.ps1

That produces dist\InterviewCopilot-windows-<version>.zip containing both executables, a config template, and a start.bat. Upload it wherever your download link points.

Running from source

# backend
pip install -r requirements-server.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# client, in two more terminals
pip install -r requirements-client.txt
python client\test_loopback_stream.py
python client\overlay_app.py

Troubleshooting

SymptomCause
Overlay says disconnectedWrong api_url, or a token mismatch. Run InterviewOverlay.exe --where-config.
Level meter flatCapturing the wrong output device. --list-devices, then --device N.
First answer takes ~50 secondsA free-tier instance was asleep. Open /health a minute beforehand.
Answers take 20+ secondsProvider rate limit, not the pipeline. The SDK waits out the 429 rather than failing.
Answers hedge or stay genericThin résumé context. The model can only be specific about what it was given.
