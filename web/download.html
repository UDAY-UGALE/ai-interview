Setting it up

  1. Unzip it anywhere. Your desktop or Documents is fine. Keep the three files together — the executables read the config file from their own folder.
  2. Fill in interviewcopilot.json. Open it in Notepad and paste in your backend's address and access token: 
    {
  "api_url": "https://your-backend.onrender.com",
  "token": "your-access-token",
  "session_id": "your-name"
}
    Both values come from whoever deployed the backend. session_id keeps your résumé and history separate from anyone else using the same server — give every person a different one.
  3. Run start.bat. It launches the audio capture and the overlay together. Two windows appear: a console showing an audio level meter, and the overlay itself.
  4. Load your résumé. Drop a PDF résumé and job description onto the overlay. This is the single biggest lever on answer quality — the model can only be specific about what it has been told.
  5. Check the level meter. Play any audio and confirm the meter in the capture window moves. If it stays flat, the wrong output device is being captured — run InterviewCapture.exe --list-devices and pass --device N.

Verifying the connection

To confirm the client can see your backend before you rely on it:

InterviewOverlay.exe --where-config

That prints every config path searched and the settings it resolved, without starting the app. If token shows (none) and your backend requires one, the config file is not being found.

What it needs

RequirementDetail
OSWindows 10 or 11. The overlay and the audio capture both use Win32 APIs.
NetworkOutbound HTTPS/WSS to your backend. Roughly 115 MB per hour of audio.
BackendDeployed and reachable, with a model-provider key configured on it.
PermissionsNone special. No admin rights, no driver, no system audio device to install.
