Hears the question. Drafts the answer. In about two seconds.

InterviewCopilot listens to a call through your system audio, works out when a real question has been asked, and streams an answer into a small window on your desktop — grounded in the résumé and job description you gave it.

What it does

Knows when a question ends

An adaptive voice-activity detector tracks the call's own noise floor, so it holds on for a pause mid-sentence and answers the moment a question is actually finished.

Answers from your résumé

Upload a résumé and job description as PDF. Answers are pitched at a practitioner in your field — its vocabulary, its metrics, its trade-offs. Nothing assumes software engineering.

A quiet overlay

A small frameless window, always on top, that reveals the answer as it streams. It stays out of the taskbar and the alt-tab list, and it is excluded from screen capture.

Ask about your screen

Send a screenshot with an optional question and get it read back through the same overlay — for a diagram, an error, or a shared document.

Type over a mishearing

When speech-to-text gets a word wrong, type the question instead. It skips transcription entirely and answers exactly what you typed.

Your keys, your server

The backend is a container you deploy yourself — Render, AWS or Azure. API keys stay on it. The desktop client never holds a credential.

How it works

Two parts. The desktop client handles everything local; your backend handles the AI.

│                          │    (wss)     │ segmentation           │

│                          │              │ speech to text         │

│                          │              │      ↓                 │
│ overlay window           │ ◄─ answer ── │ language model         │
└──────────────────────────┘   tokens     └────────────────────────┘
       no API keys                          API keys live here
  1. It hears the call. The client captures your system's audio output — the other person's voice as it comes out of your speakers — and streams it to your backend.
  2. It finds the speech. The backend detects where speech starts and stops, and groups those pieces into complete utterances rather than chopping sentences apart.
  3. It transcribes. Each segment goes to a speech-to-text model. Transcripts that turn out to be noise rather than speech are dropped.
  4. It decides whether that was a question. Rules first, then a fast classifier for the ambiguous cases, with a hard timeout so an undecided call never stalls the answer.
  5. It answers. A language model streams a reply, using your résumé, the job description, and the recent conversation.
  6. You read it. Tokens arrive in the overlay as they are generated — you see the first line while the rest is still being written.

Responsible use. Using assistance during an assessment without disclosing it may breach an employer's rules, a proctoring platform's terms, or an academic honour code. You are responsible for knowing what is permitted where you use this. See the terms.

Getting started

You need two things: a backend, and the client. The backend is a Docker image you deploy once with your own model-provider API key — it runs on a free Render instance to start with, and moves to AWS or Azure unchanged. The client is a Windows download that you point at it.
